## Retrospective: Walmart Cart Integration for the Grocery List
**Format:** Full-pipeline retro (Idea -> Refine -> Design -> Architect -> Plan -> Dev -> UAT), merged to main as `d62f2a6`
**Date:** 2026-08-29
**Facilitator:** Scrum Bag (sm)
**Duration:** timeboxed single-pass review of pipeline artifacts
**Note:** first pipeline run on this project. No prior retro to compare against — this retro sets the baseline.

### What Went Well

1. **Adversarial challenger at Refine caught a real foundational risk.** Challenge on the PRD hit confidence 2/5 over the unverified Walmart add-to-cart deep-link mechanism (`challenger/challenge.md`). PO didn't argue it away — ran an actual live browser spike (`po/spike-findings.md`) that confirmed the URL format, quantity syntax, multi-item syntax, and graceful degradation on invalid IDs. Analysis-only rebuttal would not have closed this gap; empirical test did.
2. **UX DoD self-check caught its own cross-artifact drift.** Round 1 FAIL on `03-design/dod/ux-review.md` found a component-spec revision (anchor-only cart control) hadn't propagated to `user-flows.md`/`wireframes.md`. Round 2 re-validation confirmed full propagation. The DoD process worked as designed — round 1 failing is the system working, not a defect.
3. **QA DoD caught a zero-test story before it shipped.** Story 5 QA review (`06-dev/dod/story5-qa-review.md`) went through 3 rounds: found missing component tests, then a mislabeled test (TC-SL-N01 claimed special-character coverage but tested something else), fixed both, independently reran `npm test` rather than trusting the dev's claim. Final: 16/16 TC-IDs genuinely covered, 147/147 passing, independently verified.
4. **UAT manual verification step caught the single biggest risk in the whole pipeline.** 7 of 8 "high-confidence" Walmart product IDs curated in Story 1 were fabricated — resolved to wrong or dead products. This was found only because a human-directed live-browser spot-check was actually executed (not skipped as "probably fine"). The team then went further than graceful degradation: fully re-curated all 7 IDs via real browser search rather than settling for a silently reduced feature set. Final state restores full FR-01 compliance with genuinely verified data.
5. **Sprint Plan challenger caught a fabricated citation before it became load-bearing.** The 0.8 hr/point capacity figure was credited to `architecture.md`, which the challenger actually opened and confirmed contains no such number (`05-plan/challenger/challenge.md`). Caught before the sprint committed against a fictional source.
6. **Defect process worked on a latent, zero-current-impact bug.** BUG-01 (raw-quantity fallback on unit-conversion failure) was found via exploratory static reasoning, documented with full repro and live-data-impact analysis (confirmed it doesn't reproduce with current data), fixed with an exclusion strategy, and regression-tested. Appropriately triaged as non-urgent without being ignored.

### What Went Poorly

1. **PO fabricated a source citation once.** The sprint-planning capacity math (0.8 hr/point) was attributed to `architecture.md`, which does not contain it. This is a factual defect, not a style nit — the entire 12.5-point capacity ceiling rested on an invented number dressed as a citation. Caught by the challenger, not by the PO's own review.
2. **7 of 8 curated external product IDs were fabricated at first pass.** Story 1's developer notes (`06-dev/developer/story-1.md`) explicitly labeled these "high confidence... sourced from model knowledge," not live-verified, and flagged them for human spot-check. That flag was correct and present in the artifact — but the underlying pattern (an agent stating "high confidence" about a specific unverified external fact) is exactly what produced the near-miss. It worked this time only because the verification step in the plan was actually executed.
3. **Cross-artifact sync after a design revision was not automatic.** The anchor-vs-button component-spec revision did not propagate to the upstream UX flow/wireframe docs on the first pass. It took a dedicated DoD round to catch and a second round to confirm the fix. "The revision covered it" was a false assumption the first time.
4. **A test existed with the right name but wrong content.** TC-SL-N01 claimed to cover percent-encoding of special characters but actually re-tested an unrelated case. This would have passed a check that only verifies "a test with this ID exists" — it only failed because QA read the actual assertion content against the TC-ID spec.
5. **Sprint plan enforcement mechanisms were prose-only, not gated.** The challenger flagged that both "resolved" process fixes (Sprint 2 merge-grouping constraint, recurring manual-verification checklist) were notes-to-self with no CI gate, branch-protection rule, or automated check, on a solo project where SM/PO/Dev are the same person self-reviewing. This risk was named but not structurally closed within this pipeline run.
6. **Story point sizing did not price in architecture-flagged coupling risk.** Three specific architecture risks (key-derivation duplication, shared qualification function, `useMemo` dependency desync) carried zero point premium in `stories.md` despite being called out explicitly in `architecture.md` §3.

### Root Pattern Across Both Failures (Items 1 and 2 above)

Twice in one pipeline, an AI agent stated "high confidence" about a specific external real-world fact (a citation, a product ID) that turned out to be wrong or unverifiable. Both times, the error was caught by adversarial/DoD review that actually checked the source — not by the originating agent's own guardrails. "High confidence" from a generative agent about an external, unowned fact is not evidence; only live verification (open the doc, open the browser, run the check) is.
